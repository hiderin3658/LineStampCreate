# LINEスタンプ生成スキル

シート画像1枚から、`01.png`〜`NN.png`（最大370×320・透過）／`main.png`（240×240）／`tab.png`（96×74）と、それらをまとめたアップロード用ZIPを生成する。グリッド・個数は自動推定する。あわせて、各スタンプに設定するタグの提案（`output/<名前>/タグ設定.md`）も作成する。

すべての処理はリポジトリ直下の Python スクリプトで行うため、Claude Code / Cursor / Windsurf / OpenAI Codex / Gemini CLI など、bash コマンドを実行できるエージェントであればツールを問わず動作する。コマンドはリポジトリのルートで実行すること。

## 前提

- 実行環境に Python3＋Pillow＋numpy が必要（このリポジトリでは導入済み）。
- 入力は「**白背景・1キャラ・格子配置・読み順採番**」のシート画像。
- 個人情報（クリエイター名・コピーライト等）は画像生成には不要。登録時の入力は `docs/手順書_LINEスタンプ登録から販売まで.md` を参照。

## 手順

1. **入力画像を特定する。**
   - ユーザーが画像パスを指定していればそれを使う（例: `input/Stamp_Cat2.png`）。
   - 指定がなければ `input/` 内の `Stamp_*.png` を探し、複数あれば対象をユーザーに確認する。

2. **グリッドを自動推定し設定を生成する。**
   ```bash
   python3 scripts/init_config.py <画像パス>
   ```
   - 出力された「推定グリッド（列×行＝個数）」を確認する。
   - ⚠ 個数が 8/16/24/32/40 以外、または「列または行が1」「ガター未検出」の警告が出た場合は、**そのまま進めず**ユーザーに知らせ、`config/<名前>.json` の `grid`/`count` 手動調整を提案する。
   - 既に `config/<名前>.json` がある場合は上書きされず中断する。**意図的に再生成する場合のみ** `--force` を付ける（手動調整した設定は失われるので注意）。手動調整を活かすなら init を飛ばして既存 config をそのまま手順3で使う。

3. **スタンプ一式を生成する。**
   ```bash
   python3 scripts/build_stickers.py config/<名前>.json
   ```
   - レポートの枚数・各サイズ・1MB/60MB超過の有無を確認する。

4. **生成物を目視確認する（必須）。**
   - プレビュー画像 `output/<名前>/_preview.png` を開いて（画像として表示して）、次を確認する：
     - 背景が透過され、白フチ・白い汚れが残っていない
     - キャラや文字が枠で切れていない
     - 各スタンプの切り出し位置が妥当
   - 画像表示に対応していない環境では、レポートの寸法・ファイルサイズ・警告の有無で代替確認し、ユーザーに `_preview.png` の目視を促す。
   - 問題があれば、`config` の `background.threshold`（既定240）や `feather`（既定1）を調整して再生成する。
   - `tab.png`（または `main.png`）に文字や離れた装飾（効果線・キラキラ等）が入って極小サイズで潰れる場合は、`config` の `tab`／`main` に `"isolate_subject": true` を付けて再生成する（最大の連結成分＝キャラ本体だけを残し、文字・装飾を除去する）。

5. **各スタンプのタグ設定案を作成する。**（タグはキャラではなくシチュエーションで決まる＝対応表があれば転記が正、無ければ画像から推定）
   - **まず、このシートが既定の構成（vol1〜3）に対応するか確認する。** ユーザーがvol（テーマ）を指定している、またはシートのセリフが `docs/シチュエーション別タグ対応表.md` のいずれかのvolと一致する場合は、**その対応表のタグをそのまま転記する**（キャラが変わってもタグは同じ＝正本。同一シリーズの全キャラでタグが揃う）。
   - **対応表に無い／対応が不明なシート（パーソナライズ受注など）の場合のみ**、画像から推定する：手順1のシート画像から各スタンプの言葉・感情・場面を読み取り（全コマを一度に把握できる。判別しづらいコマだけ `output/<名前>/stickers/` の個別画像で確認）、`docs/LINEスタンプ_タグ設定.md` の「利用可能タグ全一覧」に**存在する語のみ**から、関連度の高い順に1スタンプあたり4語程度を選ぶ（一覧外の語は登録できない）。
   - いずれの場合も、**全スタンプ共通でそのキャラの動物タグ（猫＝`ネコ`／犬＝`イヌ` 等。一覧の「動物」カテゴリ参照）を1つ加える**（動物タグだけはキャラ依存のため対応表には載っていない）。
   - `output/<名前>/タグ設定.md` に次の書式で出力する。冒頭に「登録数に上限がある場合は左（上位）から優先する（登録上限は最大3個）」旨と、考え方・全タグ一覧の参照先 `docs/LINEスタンプ_タグ設定.md`、対応表 `docs/シチュエーション別タグ対応表.md` を書き添える。

     ```markdown
     | # | スタンプ | 設定するタグ |
     |---|---------|-------------|
     | 01 | こんにちは | こんにちは / やっほー / はーい / ようこそ / ねぇねぇ |
     ```

   - タグ設定の対象はスタンプ画像のみ（main/tabは対象外）。

6. **結果を報告する。**
   - 生成枚数／メイン・タブ／ZIPのパスとサイズ／LINE仕様の上限内か。
   - 出力先 `output/<名前>/` と、アップロード前に `_preview.png` を最終確認するよう促す。
   - タグ登録は `output/<名前>/タグ設定.md` を見ながら行うよう案内する（考え方・全タグ一覧は `docs/LINEスタンプ_タグ設定.md`）。
   - 登録手順や登録画面の設定値は `docs/手順書_LINEスタンプ登録から販売まで.md` を案内する。

## 補足

- リジェクト等で画像を直す場合は、元シート画像を修正 → 本スキルで再生成 → ZIPを差し替える。
- 個数・グリッドの推定が外れる場合は `config/<名前>.json` を直接編集してから手順3を実行する。
- 設定スキーマ（`isolate_subject` を含む）や透過方式の詳細は `docs/設計書_LINEスタンプ生成パイプライン.md` を参照。
